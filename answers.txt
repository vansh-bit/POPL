3. 	Describe the class hierarchy (or any other chart-like structural description) of your ExTetris game / system / platform.

1. Geometric Shape Hierarchy:

- Shape (Base Class): The parent class that represents game pieces using normalized coordinate sets (r, c) instead of fixed matrices. It handles geometric operations such as clockwise and anticlockwise rotation, flipping, matrix generation, and calculations related to landing holes and cavities.

- ExTetromino (Shape): Ensures that every piece consists of exactly four connected squares, where connectivity can be through edges or corners (8-neighbourhood).

- Subclassification Facets:

- By Bounding Box: Includes Box1x4Shape, Box2x2Shape, Box2x3Shape, Box3x2Shape, Box2x4Shape, Box4x2Shape, Box3x3Shape, and Box4x4Shape. These classes use parameterized constructors instead of predefined matrices.

- By Morphology: OrthogonalTetromino represents traditional edge-connected shapes, while DiagonalPolyplet represents shapes connected through corners.

- By Landing Cavities: FlatLandingShape represents pieces with no holes, SingleCavityShape represents pieces with one hole, and MultiCavityShape represents pieces with two or more holes.

2. Supporting Subsystems:

- Board: Manages the 2D game grid, detects collisions, prevents negative wrap-around errors, clears completed lines, and calculates hole and bumpiness metrics.

- ExTetrominoFactory: Generates all 110 unique 4-polyplets algorithmically and creates their corresponding class instances.

- ExTetrisEngine: Manages the game state through a state machine with four states: READY, RUNNING, PAUSED, and GAME_OVER. It uses Observer callbacks and operates independently of the user interface.

- ShapeDistribution (Functional-OO): Handles different shape selection methods, including Uniform, Weighted, Bag, AdaptiveDifficulty, and Markov distributions. It also supports higher-order operations such as filter(), map(), and blend().

- AbstractRenderer: Provides a separate rendering interface with three implementations: CLIRenderer (ANSI terminal display for WSL), TkinterRenderer (graphical interface), and HeadlessRenderer (for testing).

- ExTetrisBuilder: Provides a simple Builder API that allows users to configure and launch different game variants without directly modifying the core code.

6. 	How do you handle the next-piece choice probability distribution?

Replaced the basic piece-selection approach with a Functional-OO Strategy Framework:

- UniformDistribution: Selects shapes randomly, giving every available shape an equal probability of being chosen.

- WeightedDistribution: Assigns probabilities to shapes based on their weights using the formula P(S_i) = w_i / sum(w_j).

- BagDistribution: Uses the 7-Bag or N-Bag randomization method to shuffle pieces while ensuring that every piece appears within a bag before repetition. This prevents pieces from being unavailable for long periods.

- AdaptiveDifficultyDistribution: Adjusts the selection of shapes according to the current board condition. It calculates board distress using the formula:

  Distress = 0.5 × (H_max / H_board) + 0.35 × (Holes / 8) + 0.15 × (Bumpiness / 15)

  When the player is struggling, the system increases the probability of safer, flat-landing shapes (FlatLandingShape). When the board is relatively clear, it increases the probability of more challenging multi-cavity shapes.

- MarkovDistribution: Uses a transition probability matrix P(S_(t+1) | S_t) to determine the next shape based on the previously selected shape, reducing the chances of immediate consecutive repetitions.

Functional Combinators:

Supports combining and modifying distribution strategies using higher-order functions such as .filter(), .map(), and .blend() (linear combination). It also supports operator overloading, allowing distributions to be combined using operators such as (dist1 + dist2) and (dist >> fn).
7. 	How do you handle game levels and speed and dynamic configuration changes in the game?

Levels & Gravity Progression:

- The game tracks the total number of cleared rows using lines_cleared. The level increases by 1 after every 10 cleared rows. The formula used is: level = 1 + (lines_cleared // 10).

- The speed at which pieces fall increases as the player progresses. The drop interval decreases according to the formula: drop_speed_ms = max(100, int(initial_speed * 0.92^(lines // 10))). The minimum drop interval is 100 milliseconds.

Dynamic Configuration & State Changes:

- Players can adjust the drop speed during gameplay using keyboard shortcuts or GUI menu options through speed_up() and slow_down().

- AdaptiveDifficultyDistribution updates the probabilities of selecting different shapes on every game tick based on the current board condition. It uses metrics such as count_holes(), get_max_height(), and get_bumpiness().

- Engine Observer callbacks automatically send updates about the score, level, and cleared rows to the renderers.

9. 	How much of the physics of the game (shape constraints like square block components, environment constraints like horizontal and vertical alignments, speed and collision effects, etc.) flexible in your system or platform? If it is indeed flexible, how easy or hard it is to program it?

Flexibility of Game Physics:

- Shape Constraints: The system supports different shape sizes through the base Shape class, which uses normalized 2D integer coordinates. Although ExTetromino is designed for pieces containing 4 blocks, other shapes such as Pentominoes (5 blocks) and general Polyominoes can also be supported by directly extending the Shape class.

- Environment / Grid Dimensions: Board dimensions are fully configurable. Users can choose different width and height combinations, such as 10×20, 12×22, or 16×30.

- Spatial Alignment & Collisions: The system maintains strict grid boundaries and prevents negative-index wrap-around errors. During rotation, it also supports wall-kick recovery by trying nearby offsets (±1 and ±2) before rejecting the rotation.

- Speed & Drop Effects: The game supports configurable soft drops (+1 point) and instant hard drops with ghost-piece projection (+2 points per cell).

Ease of Programming:

- Very Easy: Changing grid dimensions, drop speed, shape filters, scoring rules, or distribution strategies requires only a single line of modification in the Builder API or JSON configuration file.

- Moderate: Implementing non-standard physics, such as diagonal gravity or non-Euclidean grid wrapping, requires modifying the Board class methods, particularly Board.is_valid_position() and Board.clear_lines().
10. 	How do you handle ongoing game states, global system states, suspension and resumption, etc.?

State Representation:

- The game state is managed through a Finite State Machine in ExTetrisEngine with four states: READY, RUNNING, PAUSED, and GAME_OVER.

- The main state variables include cursor, current_piece, next_piece, board.grid, score, lines_cleared, level, is_paused, and is_game_over.

Suspension and Resumption:

- Pausing (toggle_pause() / P key): Stops automatic piece movement and ignores player movement and rotation inputs while preserving the board, active piece, cursor position, and timer.

- Resuming the game restarts the game loop from where it was paused without losing any progress.

State Persistence & Telemetry:

- State Saving: The current game state can be exported and saved to a text file using save_file().

- Render Composition: The get_render_composite() method combines locked blocks, the currently falling piece, and its ghost landing position into a single matrix for display.

- Board Cloning: The board.clone() method creates an independent copy of the board, allowing simulations, testing, and future game-planning functionality without modifying the original board.
